## Project

Arcade Vault ("ARCADE VAULT") — a Spanish-language retro arcade game portal web app: browse a game library, launch HTML games, save scores, and view a leaderboard ("Salón de la Fama"). See `prompt-arcade-vult.md` for the full original product/design spec (visual direction, pages, copy, interactions) — read it before implementing UI, since it defines exact Spanish copy, neon/CRT visual language, and page-by-page behavior.

Built with Next.js (App Router), React, TypeScript, and Tailwind CSS v4.

## Commands

```bash
npm run dev      # start dev server (Next.js, Turbopack)
npm run build    # production build
npm run start    # run production build
npm run lint     # eslint (flat config, eslint-config-next)
```

There is no test setup in this repo yet.

## Important: Next.js version is ahead of training data

`package.json` pins `next@16.3.6` and `react@19.2.8` — versions likely newer than this model's training data, with breaking API/convention changes from older Next.js knowledge. Before writing App Router code (routing, data fetching, layouts, metadata, etc.), check `node_modules/next/dist/docs/` (notably `01-app/`) for current conventions rather than relying on prior Next.js knowledge. This directory is regenerated by `next dev`; if `AGENTS.md` reappears in git status as a next-dev-generated file, that's expected — see its content for the same pointer.

## Architecture / current state

- `app/` is still the unmodified `create-next-app` scaffold (`app/page.tsx`, `app/layout.tsx`, `app/globals.css`) — the actual Arcade Vault UI has not been built here yet.
- `resources/templates/` is a **static HTML/JSX design prototype**, not part of the Next.js build. `resources/templates/Arcade Vault.html` loads React/ReactDOM/Babel from CDN `<script>` tags and compiles the `.jsx` files in-browser (no imports/exports, no bundler — globals like `React`, `useState` are destructured per-file, e.g. `const { useState: useStateApp } = React;` in `app.jsx`). It's a reference implementation of the intended screens, routing (hash-based, driven by `app.jsx`), and localStorage-based scoring (`av_user`, `av_scores` keys) — useful as a spec for porting into `app/`, but not code to import directly.
  - `data.jsx` — mock game data
  - `nav.jsx` — top navbar
  - `biblioteca.jsx` — game library grid (home)
  - `detalle.jsx` — game detail/launch screen
  - `reproductor.jsx` — game player screen (HUD, game-over modal)
  - `auth.jsx` — login/register screen
  - `salon.jsx` — Salón de la Fama (leaderboard)
  - `app.jsx` — hash-router + top-level state (user, route) tying screens together
  - `styles.css` — the full neon/CRT visual system (colors, scanlines, glow effects, fonts) referenced by the prototype
- When porting a prototype screen into `app/`, expect to translate: global-script JSX → proper ES module components with imports; hash-based routing in `app.jsx` → Next.js App Router routes/layouts; inline `styles.css` → Tailwind v4 (`app/globals.css` uses `@theme inline` token mapping, not a `tailwind.config`).

## Conventions

- All user-facing text (labels, buttons, nav, messages, placeholders) must be in Spanish — see `prompt-arcade-vult.md` for exact terms (e.g. "JUGAR", "GUARDAR PUNTUACIÓN", "VOLVER AL VAULT").
- Path alias `@/*` maps to the repo root (`tsconfig.json`).
- ESLint uses the flat config format (`eslint.config.mjs`) with `eslint-config-next`'s `core-web-vitals` and `typescript` rule sets.
